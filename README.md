# bazel-tanstack-spike

A TanStack Start app (`apps/web`, SSR + Nitro) and a shared React package
(`packages/ui`) in a pnpm workspace, built either with plain pnpm or with Bazel
(rules_js / rules_ts). `pnpm-lock.yaml` is the single source of truth for
dependencies.

## Tooling

Only Node.js (24) is required on the machine. pnpm comes from Corepack (pinned
by `packageManager` in `package.json`) and Bazel comes from the
`@bazel/bazelisk` dev dependency (pinned by `.bazelversion`).

```sh
mkdir -p .bin && corepack enable --install-directory .bin pnpm
export PATH="$PWD/.bin:$PATH"   # pnpm on PATH for this shell (package scripts call pnpm)
pnpm install
```

## pnpm

```sh
pnpm dev          # dev server with HMR on http://localhost:3000
pnpm build        # builds packages/ui, then apps/web into apps/web/.output
pnpm start        # serves apps/web/.output (PORT, default 3000)
pnpm test         # vitest
pnpm typecheck
```

`VITE_BUILD_CHANNEL=<value> pnpm build` sets the value shown on the home page.

## Bazel

Run Bazel through pnpm (`pnpm bazel …` runs bazelisk):

```sh
pnpm bazel build //...                    # everything, including //apps/web:build
pnpm bazel test //...                     # typecheck (app, ui) and vitest
pnpm bazel run //apps/web:server          # serves the Bazel-built app (PORT, default 3000)
pnpm bazel build //apps/web:build --define=VITE_BUILD_CHANNEL=staging
```

The build output is `bazel-bin/apps/web/.output`.

## Route tree

`apps/web/src/routeTree.gen.ts` is generated by the TanStack Router plugin and
committed. `pnpm dev` and `pnpm build` keep it up to date. The Bazel build fails
if it is stale. Run `pnpm build` (or `pnpm dev`) and commit the result.

## Dependencies

After changing a `package.json`, run `pnpm install` and commit
`pnpm-lock.yaml`. Bazel reads the lockfile directly. Packages that need
install scripts must be listed under `allowBuilds` in `pnpm-workspace.yaml`.
